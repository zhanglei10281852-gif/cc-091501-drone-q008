# 无人机运行领域约定

服务面向低空运行、机队运维和合规管理人员。时间字段统一使用带时区的 ISO 8601 字符串，位置、授权和设备事件应保留来源时间与接收时间，不能用展示层文字替代结构化状态。

健康接口只表示进程存活，不代表任何飞行或审批业务已经完成。需要落盘的数据应使用运行时配置指定的位置（`AIRWORTHINESS_DATA`），测试不得依赖主机上的隐藏状态。

## 适航管理补充约定

- 一切历史均按时间点查询：拆装、固件、检查、工单、任务、飞行日志都带带时区时间戳；“当前配置”只是时间点查询在当下的结果，任何装配变更不得改写历史时刻的配置结论。
- 可序列化部件的寿命依据必须可溯源：装机时同步既往循环/小时读数，缺读数不得装机；在翼寿命 = 同步基线 + 该装机区间内实际飞行。
- 放行结论只有结构化状态（GO / NO_GO / EMERGENCY_GO）与阻断项，不用自由文本代替。
- 检查事实与签字资质分开保存：即使签字人资质已过期，检查记录仍须留痕；资质有效性以签字时刻为准，在放行评估时判定。
- 紧急放行是独立角色（监管人员）的权力，必须带明确失效条件（失效时刻、可用次数、绑定任务、可覆盖阻断清单），且不得豁免结构、寿命、固件、占用与环境类硬性阻断。
- 飞行日志必须同时保留飞行发生时间（`offBlockAt`/`onBlockAt`）与受理时间（`receivedAt`）；迟到日志补计后，系统给出受影响任务、历史放行评估与复检范围。
- 信息按岗位裁剪：机务视图含寿命与签字依据，调度视图只含结论与阻断项；跨岗位访问返回禁止。
